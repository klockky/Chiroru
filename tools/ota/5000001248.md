# 5000001248: профиль из OTA, KernelSU проверен на устройстве

Кандидат включён в **0.7.3-rc1 / versionCode 32**, с меткой **OTA test**.
Станция во время анализа работала на `5000001245`; на ней использовался только
существующий root и аппаратный crypto driver для расшифровки файла OTA.
В rc2 KernelSU проверен на установленной `1248`; отдельные режимы In-app root
и ADB root пока не проверены.

### Исправление 0.7.3-rc2 / versionCode 33

Первый запуск rc1 на `1248` проходил проверку Image header, но завершался
`FAIL own task not found`. Заголовок и `memstart_addr` читались через один
виртуальный слот PTE. Очистка PTE не инвалидирует TLB, поэтому повторное
отображение могло вернуть ноль из страницы заголовка вместо `memstart_addr`.
В rc2 каждое отображение получает новый слот, включая проверку заголовка,
чтение globals и начало обхода задач. Host-регрессия моделирует сохраняющийся
TLB для всех четырёх профилей; возврат ошибки rc1 заставляет тест падать.

На устройстве rc2 успешно прочитал ненулевой `memstart_addr`, нашёл собственную
задачу и завершил root stage с `uid=0 euid=0`. `ksud rc=0`, все четыре vendor
символа разрешены; `post-fs-data`, `services` и `boot-completed` вернули `rc=0`,
`lifecycle: status=complete`. Внешний `adb shell su -c id` подтвердил UID 0 и
контекст `u:r:ksu:s0`; после загрузки SELinux — Enforcing. Успех на второй
попытке reclaim. Повторная загрузка после перезагрузки ещё не проверена.

## Сравнение с 1245

- Встроенная kernel config совпала побайтно.
- Все 43 482 общих уникальных имени текстовых символов имеют одинаковые
  смещения относительно `_stext`. Различия `.llvm.*` имён не используются
  как критерий совместимости.
- У штатного Mali `r25p0-01rel0`, UK API 11.21. Все allocated sections,
  кроме `.modinfo` и build ID, совпадают с `1245`; в частности, совпадает
  машинный код. `module_layout` CRC — `0x8395960f`.
- `init_task` (проверенный диапазон 0x800 байт) и `init_mm` (0x300 байт)
  в исходных Image совпадают. Это начальные структуры, не runtime dump.
- Код `__arm64_sys_getuid`, `__set_task_comm`, `syscall_trace_enter`,
  `copy_init_mm`, `__primary_switched`, `selinux_cred_prepare`,
  `context_add_hash`, `prepare_creds` и `commit_creds` совпадает побайтно.
- В проверенных seccomp/AIO/SELinux-функциях отличия инструкций относятся
  к адресации констант/строк; используемые offsets task/cred/SELinux/VFS
  сверены отдельно, а не выведены только из совпадения текстовых символов.
- Bootloader и DTBO **не идентичны** `1245`. Поэтому фактический physical
  load address и поведение после загрузки требуют аппаратной проверки.

## Найденные адреса

Все смещения ниже получены из Image/ELF `1248`:

| Объект | Смещение от начала Image | Основание |
|---|---|---|
| `_stext` | `0x800` | Восстановленный kallsyms/ELF mapping |
| `sys_call_table` | `0xEEEF18` | Семь независимо проверенных syscall slots |
| `init_task` | `0x1277500` | `__primary_switched`: адрес, записанный в `sp_el0` |
| `init_mm` | `0x12BF060` | `copy_init_mm`: аргумент `dup_mm` |
| `selinux_state` | `0x147D310` | `selinux_init`, `enforcing` находится по `+1` |
| `selinux_blob_sizes` | `0xFE2F84` | `selinux_cred_prepare`: смещение security blob |
| `memstart_addr` | `0xFE2310` | `arm64_memblock_init`: запись выровненного начала RAM |
| `kimage_voffset` | `0xFE2320` | `__primary_switched`: запись VA − PA |
| `vabits_actual` | `0x1017F28` | `arm64_memblock_init`: вычисление linear region size |

Таким образом, `sys_call_table - _stext = 0xEEE718`, в отличие от `0xEEE700`
у `1245` и `0xEEE6E8` у `1307`. Перенос адреса соседней прошивки неверен.
Остальные четыре vendor-поля и используемые task/cred offsets совпадают с
проверенной arm64-схемой.

Начальный physical Image base кандидата — `0x1080000`, как у существующих
профилей. Перед чтением globals и изменением credentials native-код проверяет
по этому адресу magic `ARMd`, `text_offset=0x80000` и `image_size=0x14B7000`.
При несовпадении операция прекращается. Калиброванный `lbase_magic` от `1245`
не используется: linear base вычисляется из runtime `memstart_addr` и
`vabits_actual`; `_stext` — из runtime `kimage_voffset`.

## Сборка и проверки

```sh
python3 tools/build-kernel-modules.py 5000001248 /path/to/prepared-kernel /tmp/opencode/modules-1248
```

| Модуль | SHA-256 |
|---|---|
| `chiroru_adb.ko` | `6a74f8bbdf1ddeb46bc1d54cd2de75ec219616733eba18c5795ed5c8789c5c0a` |
| `kernelsu.ko` | `812178a7a3bfe645aebf92615b1370f8206c77e6411ca6481b90a393961d776f` |

Оба модуля пересобраны с точным vermagic `1248`; ADB release guard задан при
компиляции. Менеджер — официальный v3.4.2/versionCode 33355; `ksud` и клиент —
общие arm64-ресурсы. Exact gates проверяются на смешанных признаках `1245` и
`1248`, на соседнем неизвестном номере и на всех остальных профилях.

Проверка сборки 0.7.3-rc1: 110 JVM/UI-тестов, release lint, native/host tests,
проверка каталога и ресурсов всех четырёх профилей в готовом APK. Module build
checks проверили vermagic, CRC, ADB release guard и SELinux policy dependencies.

Оставшаяся проверка: отдельно после перезагрузок In-app root, ADB root и
автозагрузка KSU; для каждого — Enforcing и ожидаемый SELinux контекст.
До завершения матрицы статус профиля — кандидат.
