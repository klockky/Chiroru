# Прошивка 5000001364

Профиль проверен по расшифрованному OTA и на станции с этой прошивкой:
In-app root, ADB root, KernelSU и его автозагрузка работают.

## Проверка на станции

На `5000001364` с Chiroru `0.7.8-rc1` / 45 выполнен `root+ko`:
модуль KernelSU загружен, `post-fs-data`, `services` и `boot-completed`
завершились с `rc=0`, итог — `lifecycle: status=complete`.
Через ADB команда `su -c id` подтвердила `uid=0`, контекст `u:r:ksu:s0`.
SELinux восстановлен в Enforcing, `kptr_restrict` — в `2`.
Root сохранился после остановки и повторного открытия Chiroru;
приложение и ADB-монитор снова работают под обычным UID приложения.

После перезагрузки отдельно проверен In-app root: процесс получил UID 0,
root-console прошла встроенную проверку в домене `chiroru_console`,
SELinux восстановлен в Enforcing. Затем проверен `root+adb`: загружен
`chiroru_adb`, клиент через ADB получил UID 0 в домене `chiroru_adb`,
`kptr_restrict` восстановлен в `2`. ADB root сохранился после перезапуска
приложения. При отключении ADB через Android settings монитор восстановил
подключение за 13,4 секунды.

Для проверки автозагрузки временно задана задержка 30 секунд. После
перезагрузки KernelSU загрузился с первой попытки; полный boot-отчёт
сохранён: начало на 35,618 с, завершение на 44,402 с uptime,
`lifecycle: status=complete`, SELinux Enforcing и `kptr_restrict=2`.
Исходные настройки Chiroru восстановлены побайтно, список отключённых
пакетов не изменился.
