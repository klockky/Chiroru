## Проверка на станции

На `5000001388` с Chiroru `0.7.8-rc2` / 46 отдельно проверены:

- In-app root: процесс получил UID 0, root-console прошла встроенную
  проверку в домене `chiroru_console`, SELinux восстановлен в Enforcing.
- ADB root: загружен `chiroru_adb`, клиент получил UID 0 в домене
  `chiroru_adb`, `kptr_restrict` восстановлен в `2`. Root сохранился
  после остановки и повторного открытия приложения.
- ADB-монитор: после отключения ADB через Android settings подключение
  восстановилось за 30,7 секунды, включая переподключение с ПК.
- Автозагрузка KernelSU с временной задержкой 30 секунд: модуль загружен
  с первой попытки, `post-fs-data`, `services`, `boot-completed` завершились
  с `rc=0`, итог — `lifecycle: status=complete`. Полный boot-отчёт сохранён:
  начало на 35,57 с, завершение на 44,13 с uptime.

Через ADB команда `su -c id` подтвердила UID 0 в домене `ksu`.
SELinux — Enforcing, `kptr_restrict=2`; KernelSU root сохранился после
перезапуска приложения. Исходные настройки Chiroru восстановлены побайтно,
список отключённых пакетов не изменился.
