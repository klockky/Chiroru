# Приложение Chiroru

Пакет — `dev.chiron.chiroru`. [Поддерживаемые прошивки](FIRMWARE.md).

## Режимы

Способ выбирается в **«Настройках»** и запускается кнопкой на главной.

| Режим | Результат | Срок действия |
|---|---|---|
| Probe | Диагностика драйвера Mali | Один запуск, без root |
| In-app root shell | Root-консоль внутри Chiroru | Пока жив процесс приложения |
| ADB root shell | Модуль `chiroru_adb` и клиент `chiroru-su` | До перезагрузки станции |
| KernelSU | Модуль KernelSU и запуск его служб | До перезагрузки станции |

Во время получения root интерфейс приостанавливается. Результат появляется
в журнале после завершения операции.

## Консоль

Во вкладке **«Консоль»** введите команду и нажмите **«Выполнить»** или Enter.
Кнопка **«Стоп»** завершает группу процессов команды, включая обычные конвейеры.

- In-app root запускает команды в домене `chiroru_console`, с UID 0 и Enforcing.
  Root включён постоянно; рабочий каталог и `HOME` — `/`.
- В режиме ADB root используйте переключатель **Root**.
- После загрузки ADB-модуля или KernelSU консоль предлагает перезапустить Chiroru.
  Модуль остаётся в ядре. Для In-app root перезапуск не нужен.
- Без root команды выполняются с правами приложения, из его `filesDir`.

Каждая команда запускается в новом shell. Для смены каталога используйте,
например, `cd /data/local/tmp && ls -la`: отдельный `cd` не влияет на следующий
запуск. PTY и ввод stdin не поддерживаются, поэтому `vi`, интерактивный `top`
и `read` здесь не работают.

Вывод ограничен последними 65 536 символами; его можно выделить и скопировать.
Команды и вывод не сохраняются на диск. Отделившиеся от группы daemon-процессы
не завершаются кнопкой «Стоп».

Root с компьютера после включения ADB root:

```sh
adb shell -t /data/local/tmp/chiroru-su
adb shell /data/local/tmp/chiroru-su -c 'id; getenforce'
```

Обычный `adb shell` сохраняет UID 2000. Подробности:
[In-app root](../../root-console/README.md), [ADB root](../../adb-root/README.md).

## KernelSU и менеджер

На `5000001307`, `5000001245`, `5000001248`, `5000001289`, `5000001321`, `5000001346`, `5000001364` и `5000001388` используется официальный
KernelSU Next Manager v3.4.2. Если его нет, Chiroru скачивает и устанавливает
его после загрузки модуля. Для первого скачивания нужен Интернет.

На factory нужен встроенный armv7-менеджер. Установите его кнопкой
**«Установить совместимый менеджер»**, затем вернитесь в Chiroru и запустите
KernelSU. Если Android запросит разрешение на установку из Chiroru, выдайте его
и нажмите кнопку снова.

Пакет, версия и сертификат менеджера должны соответствовать профилю.
Несовместимый установленный менеджер блокирует запуск KernelSU; приложение
не заменяет его автоматически. [Сборка factory-менеджера](../../tools/factory/README.md).

Ошибки скачивания или установки менеджера не выгружают KernelSU.
Кнопка **«Повторить установку менеджера»** повторяет только установку.
Если не выполнились скрипты модулей, журнал показывает ошибку служб отдельно
от результата загрузки KernelSU.

## Автозагрузка

Автозагрузка KernelSU по умолчанию выключена.
Задержка задаётся в настройках: 0–86400 секунд от включения станции,
по умолчанию 180. Изменение задержки пересчитывает ожидающий запуск.

На factory заранее установите менеджер. После OTA с неизвестной прошивкой
автозагрузка прекращается; причина записывается в boot-отчёт.

### Поддержание ADB

Переключатель **«Поддерживать ADB включённым»** по умолчанию выключен.
Фоновая служба проверяет `Settings.Global.adb_enabled` сразу после включения
и каждые 30 секунд, восстанавливая значение `1` при необходимости.
Служба работает в отдельном процессе с уведомлением, независимо от KernelSU,
и запускается после загрузки станции и обновления APK.

Разрешение `WRITE_SECURE_SETTINGS` выдаётся приложению автоматически после
успешного root любым из трёх способов. Ручная выдача:

```sh
adb shell pm grant dev.chiron.chiroru android.permission.WRITE_SECURE_SETTINGS
```

Отключение переключателя прекращает проверки, не разрывая текущее подключение.
После принудительной остановки приложения откройте Chiroru, чтобы возобновить
работу службы. Права root через ADB настраиваются отдельно.

## Запуск через ADB

```sh
adb install -r Chiroru.apk
adb shell am start -n dev.chiron.chiroru/.MainActivity
```

Для запуска операции передайте `--es mode` при открытии нового процесса:

| Значение | Операция |
|---|---|
| `probe` | Диагностика Mali |
| `root` | In-app root |
| `root+adb` | ADB root |
| `root+ko` | KernelSU со службами |
| `root+ko-safe` | KernelSU без скриптов запуска модулей |

Пример:

```sh
adb shell am start -n dev.chiron.chiroru/.MainActivity --es mode probe
```

Повторная доставка intent в уже открытый экземпляр не запускает операцию заново.

## Сборка и проверки

Нужен полный checkout с сабмодулем KernelSU (`git submodule update --init --recursive`),
Linux, JDK 17, Python 3, C-компилятор,
Android SDK platform/build-tools 36, NDK `28.2.13676358` и CMake `3.22.1`.

Из этого каталога:

```sh
./build-apk.sh
./build-apk.sh --debug
./gradlew :app:testDebugUnitTest :app:lintRelease \
  :app:testFirmwareCatalog :app:testNativeFirmwareProfiles \
  :app:testNativeProcessWait :app:testConsoleRunner :app:testProcessConsole
```

Скрипт использует `JAVA_HOME`, а при его отсутствии ищет JDK 17.
SDK определяется через `ANDROID_HOME`, `ANDROID_SDK_ROOT` или `$HOME/Android/Sdk`.
В Android Studio откройте этот каталог как Gradle-проект с JDK 17.

Результат — `Chiroru.apk` или `Chiroru-debug.apk` в этом каталоге.
Локальная подпись берётся из `$HOME/.android/debug.keystore` и может отличаться
от подписи CI. Неподписанный APK: `./gradlew :app:assembleRelease -Pchiroru.unsigned=true`.
Модули и демоны берутся готовыми из assets;
[их пересборка](../../tools/KERNEL_MODULES.md) выполняется отдельно.

JVM/UI-тесты используют Robolectric и подставные обработчики. Host-тесты
проверяют каталог, адресацию окон, ожидание процессов и консольный протокол.
Они не запускают root на станции. `preBuild` сверяет профили, backend ID
и SHA-256 ресурсов; готовый APK проверяет `app/scripts/verify_release_apk.py`.

`ManagerDeviceTest` проверяет файловый ввод-вывод и скачивание официального
менеджера на Android, без получения root и установки менеджера. Для него
используйте отдельный пакет `dev.chiron.chiroru.preflight`:

```sh
./gradlew :app:connectedDebugAndroidTest -Pchiroru.preflight=true \
  -Pandroid.testInstrumentationRunnerArguments.class=dev.chiron.chiroru.ManagerDeviceTest
```

Для обычной сборки параметр `chiroru.preflight` не нужен.
